Leamonde AI · System Overview

A family staff made of AI.

A chief of staff, a personal chef, a shopper, a card strategist, an interior designer, and a coffee specialist. They share a Discord server with the two of us to plan dinners, compare groceries, source furniture, track card perks, and file medical claims, all running on a server in our house.

Aida · Cookie · Scout · Sterling · Sloan · Tazza
Why Discord?

Both partners can talk with the staff in shared rooms or step into locked 1-on-1 desks. The mobile app already handles voice notes, photos, threads, and approval buttons.

Why a home Proxmox server?

One virtual machine on our home server runs the Python agent service, three SQLite databases, and local browser containers. Conversations and household records stay on our own disk.

Why two Gemini models?

Gemini Argon handles live conversation where judgment matters. Gemini Flash handles heavy web reading in parallel sub-agents, checks draft replies before they post, and scripts voice briefings.

Why MCPJungle and 1Password?

All local and cloud tools connect through one local gateway. API keys and logins are fetched from 1Password on demand, so no static passwords sit in config files.

04A · Storage

Three Backing Stores

1. Git Handbook & House Binder 60s reload

Agent instructions, schedules, permissions, and shared household notes live in a Git repo that reloads every 60 seconds. When an agent saves a new family note or you approve a permanent tool rule in Discord, the server commits and pushes that change back to Git.

2. Three Local SQLite Databases Pinned boards

Structured records stay in three local SQLite files: Kitchen DB (meal plans, pantry, grocery list, lunchbox history), Perks DB (card benefits, reset dates, subscription checks), and Usage DB (token counts and monthly cloud spend).

3. Thread Logs & Throwaway Routines Lean context

Each Discord channel and thread keeps its own conversation log on disk. Scheduled morning briefings and inbox watches run in fresh throwaway sessions so daily status posts do not pile up in your chat history.

04B · Boundaries

How Secrets and Data Stay Safe

No static passwords on disk

API keys, bot tokens, and website logins are fetched from 1Password in memory when needed. Every secret is registered with an output filter that replaces raw values with [redacted] before anything reaches Discord or a log file.

Never guess credentials

Agents are forbidden from guessing usernames, emails, passwords, or 1Password item names. Browserless blocks plain-text typing into password fields and pauses all logins across the server for 15 minutes if any login fails.

Hard channel and tool boundaries

Personal Gmail and calendar tools are only attached inside that partner's private desk. Instacart has no checkout or place-order code at all, and the Monarch Money integration strips out bank balances, paychecks, investments, and net worth.

05 · Day-to-Day Operation

Keeping Replies Accurate and Cloud Bills Low

Parallel Flash sub-agents

When an agent needs to read retail pages or documentation, it spawns up to four read-only Gemini Flash sub-agents. They read the full pages and return a short summary, keeping raw HTML out of the main Argon conversation.

Two-step reply check

Before any reply posts to Discord, a fast rule check blocks invented links, fake Amazon IDs, and uncalled tools. Then a Gemini Flash reviewer checks the draft against that specialist's rules and the tool outputs from that turn.

Routine graduation

Scheduled routines load only the three to five tools they actually need. New routines start on Gemini Argon while Flash quietly replays the same tool outputs in the background; after three matching runs, an #ops button lets you switch that routine to Flash.

Pull deploys with auto-rollback

Every five minutes the server checks Git for updates. When nobody is mid-conversation, it pulls the new code, runs eight live checks against 1Password, MCPJungle, and Gemini, and rolls back automatically if any check fails.
